# External boundaries

> Part of the [architecture docs](../ARCHITECTURE.md). `file:line` references can drift; search for the symbol name if a line doesn't match.

## File system
- Local files and folders, by path, up to 16 open at once in tabs (`MAX_TABS`). A folder is one table of every `.parquet` file below it (ADR 0006, `parquet_reader::dataset`): searched in path order, skipping names that start with `.` or `_`, at most 16 folder levels (`MAX_FOLDER_DEPTH`), 100,000 directory entries (`MAX_FOLDER_ENTRIES`), 4,096 files (`MAX_DATASET_FILES`) and 256 MB of footer metadata (`MAX_DATASET_METADATA_BYTES`). Files may differ (ADR 0019): columns are merged by name (missing ones read as null) and types widened by `types::common_type`, else the open fails naming both files; `key=value` folders become partition columns (`Int64` if every value is an integer, else `Utf8`). Symbolic links are followed, within the depth limit. No globbing, URLs or object storage.
- Each file is **re-opened by path for every read** (a read that crosses files opens each); metadata is cached from open time. Each local file's size and modification time are recorded with its footer, and a read of a file whose size or time differ fails with `FileChanged` instead of using the old footer against new bytes (ADR 0018). The app checks the open tab's file or folder every 2 seconds (`ParquetSource::check_changed`: one `stat` per file and per searched folder; for a CSV, JSON or Arrow file, the original) and offers Reload. Remote objects are not checked. A file rewritten with the same size and modification time is not noticed.
- Writes: export target (+ temp file next to it) and the session JSON.

## Network (ADR 0008)
- `https://`, `http://`, `s3://bucket/key`, `gs://bucket/key` and `az://account/container/blob` URLs, one object each (no prefix listing). Requests are blocking `ureq` GETs on the worker threads; TLS uses `rustls` with the operating system's root certificates.
- A Parquet object on a server that answers `Range` requests is read in place: the footer at open, then the column chunks each read needs, through `remote::RemoteReader` (a `ChunkReader`). Ranges up to 128 MB are cached per object, 256 MB together (`REMOTE_CACHE_BYTES`). Otherwise, and for CSV, JSON and Arrow objects, the object is downloaded to `<temp>/pavi-download-<pid>-<n>/` (≤ 32 GiB, `MAX_DOWNLOAD_BYTES`) and opened as a local file.
- Credentials only from the environment: `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN` or `~/.aws/credentials` (`AWS_PROFILE`), signed with SigV4; `AWS_REGION`, `AWS_ENDPOINT_URL` for S3-compatible stores; `GOOGLE_OAUTH_ACCESS_TOKEN`; `AZURE_STORAGE_SAS_TOKEN`. Pre-signed URLs work as they are. Without credentials requests are anonymous.
- Timeouts: 15 s to connect, 30 s for the response headers, 300 s for a body; 3 attempts on connection errors and 5xx answers. A request in flight can't be interrupted.
- A URL is shown without its query string, and a URL with a query string is never saved in the session.

## Other file formats (ADR 0007)

| Format | Extensions | Read as | Limits |
|---|---|---|---|
| CSV | `.csv`, `.tsv`, or any file read as CSV | Import options (ADR 0020), each guessed unless given: delimiter (tab for `.tsv`, else the most frequent of `,` `;` tab `|` in the first line), header line (else `column_1`, …), encoding (UTF-8, UTF-16 LE/BE, Windows-1252; detected from the first 64 KB), every column as text. Types inferred from the first 10,000 records (`MAX_INFER_ROWS`): integers, floats, booleans, dates, timestamps, else text; empty fields are null | A later value that doesn't fit its column's type makes the file be read twice more: once to choose types from every value, once to convert. Only a value that still doesn't fit stops the open |
| JSON | `.json`, `.jsonl`, `.ndjson`, or any file read as JSON | One object per line, or one array of objects. Types inferred like CSV; nested objects become structs, arrays become lists. Encoding and every column as text as for CSV | Same as CSV; a field first seen after the inferred records also triggers the second pass (strict mode) instead of being dropped |
| Arrow IPC | `.arrow`, `.feather`, `.ipc`, `.arrows` | File format (Feather v2, `ARROW1` magic) or stream format; LZ4 and Zstd buffers | Feather v1 is refused. Each record batch is read whole. Before reading, every block and message must lie inside the file; metadata messages are capped at 64 MB and a compressed buffer at 1 GB uncompressed |

| Excel / OpenDocument | `.xlsx`, `.xlsm`, `.xlsb`, `.xls`, `.ods`, or any workbook read as Excel | One sheet: the first worksheet, or one named (ADR 0021). First row names the columns unless "no header". Types from every cell: whole numbers, floats, booleans, dates, timestamps, durations, else text; error cells are null (text in text columns); empty rows between data rows kept | `.xlsx`/`.xlsm` streamed cell by cell, their shared parts ≤ 256 MB uncompressed (`MAX_EXCEL_SHARED_BYTES`); `.xlsb`/`.ods` ≤ 256 MB uncompressed and `.xls` ≤ 256 MB (`MAX_EXCEL_WHOLE_BYTES`), read whole; ≤ 16,384 columns. Formulas read as their cached values |

All are read into a temporary Parquet file of at most 32 GiB (`MAX_CONVERTED_BYTES`) before the first row shows. Other extensions are opened as Parquet. ORC is not supported (see the ADR).

Export writes CSV, Parquet, JSON Lines (`.jsonl`), Arrow IPC file format (`.arrow`) and Excel (`.xlsx`, one sheet of at most 1,048,575 rows; ADR 0021).

## Parquet/Arrow features
| Feature | Status |
|---|---|
| Column projection | Top-level roots only (`ProjectionMask::roots`); nested columns are read whole (tested: `source.rs:1735`) |
| Row-group pruning | For filters, using min/max stats. Each top-level column is mapped to its Parquet leaf (`statistics::leaf_columns`), so plain columns of a file with nested columns are pruned too; a test on a nested column never rules a group out. Decimals stored as byte arrays are not pruned. |
| Page index / bloom filters | Not loaded with the footer. A filtered scan reads them per row group for the columns it tests (ADR 0014): the page index skips pages whose min/max rule the filter out (same rule as row groups; a chunk's index ≤ 4 MB), and a bloom filter skips row groups an `==` value is absent from (ints, `Date32`, text, binary; filter ≤ 16 MB, its length recorded in the footer). |
| Display formatting (`value.rs`) | Ints, floats and bools via `Display`; strings (Utf8/LargeUtf8/Utf8View) as-is; binary types as hex; dictionary cells show the referenced value. Dates, timestamps, times, durations, intervals, decimals, Float16 and run-end-encoded values use arrow-cast's rules: `2022-01-08`, naive `2023-11-14T22:13:20`, zoned `2023-11-14T23:13:20+01:00` (UTC as `Z`), `123.45`, `PT90S`. `Date64` shows as a date-time. List/LargeList/FixedSizeList/Struct/Map are bounded (≤8 deep, ≤16 items). |
| Read types (`types::read_type`) | A dictionary-encoded column (pandas' categoricals, for one) is read as its values, and a Decimal256 of up to 38 digits as the Decimal128 that holds it exactly: the schema says so from the moment the file opens, and each decoded batch is cast (`reorder_batch`). Every feature below then treats them as those types. |
| Comparable types (`types::is_comparable`) | Bool, ints, floats, Decimal32/64/128 (any precision and scale), Utf8/LargeUtf8/Utf8View, Date32/64, Timestamp (any unit, with or without a time zone), Time32/Time64 (any unit), Duration (any unit), Binary/LargeBinary/BinaryView/FixedSizeBinary (byte by byte), and dictionaries of these. Not: Decimal256 wider than 38 digits, intervals, nested. |
| Filter types | Comparable types. Bool supports `==`/`!=`; `contains` and `LIKE` are text-only, except `* contains text` (ADR 0022), which matches the shown text of every column, ignoring case, and scans without statistics pruning; `IS [NOT] NULL` works on every type. Decimal literals are read in the column's scale (exact when they have no more decimals than the column; otherwise they fall between two values, so `==` matches nothing). Times are `HH:MM:SS[.fff…]`. Durations are a number in the column's unit or ISO 8601 as the grid shows them (`PT90S`, `P1DT2H30M`, `-PT0.5S`; weeks, days, hours, minutes, seconds); a value between two ticks matches nothing with `==`. Binary values are hex, with or without `0x` (`bin == 0x6869`), compared byte by byte; statistics don't prune binary columns. |
| Sort types | Comparable types; up to 8 keys. Any number of rows: past 1,048,576 rows / 128 MB the sort spills to temporary files (ADR 0005), up to 32 GiB. |
| MIN/MAX/GROUP BY types | Comparable types; results keep the input type (including time zone, decimal precision and scale). SUM/AVG (`types::is_summable`): ints, floats and decimals. A decimal SUM is `Decimal128(38, scale)` and fails past 38 digits; AVG is a float in the column's units. |
| CSV export types | every non-nested type, as the shared display text (ISO dates, RFC 3339 timestamps, scaled decimals) |
| Profiling types | Comparable types. Numbers and decimals get a mean and histogram, text gets lengths, dates, timestamps, times and durations are ordered by their value (not text), binary by its hex (the same order as its bytes). |
| Statistics display | Rebuilt as the column's Arrow type and formatted like grid values: unsigned integers, dates, times, timestamps (in their zone), durations (`PT90S`), decimals (INT32/INT64/byte-array storage) and binary (hex, even when the bytes are text). INT96 and other physical types show the stored value. In files with nested columns the plain columns keep their statistics; nested columns have none. |
| Nested values | Grid: one bounded line. Inspector: a tree of list items, struct fields and map entries (`value::value_tree`: ≤8 levels, ≤100 children per node, ≤2,000 nodes). Charts: decimals as numbers in their units, times in their stored unit. |
| Files written by polars (the repo's sample data) | Strings load as `LargeUtf8` (e.g. `dummy_5m`, `dummy_1b`), which every operation accepts like `Utf8`. |
| Large files | Row counts are `u64`. The source grid shows files over 500,000 rows through a moving 500,000-row window with its own scrollbar, so every row (including the last of a billion) is reachable. Filter, SQL and sort results hold ≤ 32,768 rows at a time around the view, with a scrollbar for the whole result; any row can be jumped to (ADR 0012). A filter's size is counted in the background; a jump into a counted filter reads at most one row group before its target, while a jump back in a SQL or sort result runs it again |

## Platform-specific code
- No `cfg(target_os)` anywhere. The few platform differences are decided at run time from `std::env::consts::OS` by small functions that take the OS name, so every platform's branch is tested on any machine:
  - Session folder (`session::session_dir`): `%LOCALAPPDATA%\PAVI` on Windows, `~/Library/Application Support/PAVI` on macOS, `$XDG_STATE_HOME/pavi` or `~/.local/state/pavi` on Linux and the BSDs; the temp folder when none of these can be found.
  - Text font (`theme::font_files`): Segoe UI on Windows, Arial on macOS, Noto Sans or DejaVu Sans on Linux; egui's built-in font otherwise.
  - Window frame (`app::native_window_frame`): decorations are disabled except on macOS. Elsewhere the top bar is the drag area and draws its own minimize/maximize/close controls (`show_top_bar`, `window_controls` in `ui/toolbar.rs`), and `window_resize_handles` puts drag strips on the edges and corners that send `ViewportCommand::BeginResize`. winit doesn't support that command on macOS, so there the system title bar and border stay.
- Builds and tests run on Windows, Ubuntu and macOS in CI. The app's window has not been checked by hand on macOS.
- Native dialogs: `rfd` (synchronous). Clipboard: egui/winit.

## unsafe / FFI
None in workspace code. Native code exists only transitively (zstd-sys, OpenGL via glow, OS dialogs via rfd).
